# 作業時間集計システム（React / Nodeなし）

これは **GitHub Pages にそのままアップロードできる静的Webアプリ** です。ビルド作業は不要です。

## まず見る方法（Supabaseの前）

1. このフォルダの `index.html` をPCのブラウザで開く。
2. 最初は **デモモード**。サンプルの作業者・工程・作業時間が見える。
3. `現場用 / 作業者画面` で、カメラまたは手入力で次を試す。

   - `OP:OP001`
   - `JOB:LASER`
   - `ACT:START`
   - `ACT:STOP`

   材料切れ・急ぎ仕事・NGは、作業中にだけ表示される「中断・問題を報告」から記録する。例外用QRは使わない。

## この版の考え方

- 現品票は必須にしていない。まず **工程別・作業者別の作業時間** を集計する。
- 一人ひとりが自分のQRで開始・終了する。二人で30分作業した場合、工程の経過30分とは別に、投入工数は60分・人として集計できる。
- 翌日に別の人が続ける場合も、同じ工程QRで新しい作業記録を開始するだけ。
- 材料切れ・設備トラブルは中断として別記録にする。待ち時間を実作業時間に混ぜない。
- 急ぎ仕事への切替は、その人の記録だけを終了する。他の人は継続できる。

## Supabaseをつないだ後の順番

1. Supabaseで新しいプロジェクトを作る。
2. SQL Editorで `supabase.sql` を全部実行する。
3. Authenticationで、まず「現場端末用」1名と「管理者用」1名を作る。
4. SQL末尾のコメントのとおり、管理者アカウントだけ `admin` に昇格する。
5. `config.js` に **Project URL** と **publishable key** を貼る。
6. 最初に `admin.html` で現場端末用アカウントにログインする。以降、その端末では作業者はQRを読むだけ。
7. GitHubのリポジトリにフォルダ内のファイルを全部アップロードし、Pagesを有効にする。

## QRコードの内容

| 用途 | QRに入れる文字 |
|---|---|
| 作業者 | `OP:OP001` |
| 作業指示 | `JOB:LASER` |
| 開始 | `ACT:START` |
| 終了 | `ACT:STOP` |

この4種類だけを使う。`admin.html` の **QRラベルを発行** から、印刷用QRを作れる。

## 大切な安全ルール

- `config.js` に書くのは **publishable keyだけ**。
- `service_role` または `secret key` は、GitHub・HTML・JavaScriptに絶対に入れない。
- GitHub Pages上でカメラを使うときはHTTPSになるので、スマホ・タブレットからQR読取ができる。
